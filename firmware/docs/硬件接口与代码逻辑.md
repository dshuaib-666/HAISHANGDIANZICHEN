# dual_scale 固件（fw_v2）硬件接口与代码逻辑说明

- 对应工程：`MDK-ARM/dual_scale.uvprojx`，输出 `MDK-ARM/dual_scale/dual_scale.hex`
- 本说明只描述**当前代码树里已经编译、已经调用**的行为；依据为 `Core/Src`、`Core/Inc`、`dual_scale.ioc` 和 `.uvprojx` 的源文件清单
- 一句话概括：STM32F407 裸机双通道称量固件。TIM2 以 10 Hz 轮询两路 RS485 称重模块的**内码**，DWT 打 µs 时间戳；A 轨增量算法（变化沿 + 延迟 Hampel + 45 s 自对齐 + 三次插值配对 + 比值 + 估计器）算出锁定重量；数码管 5 Hz 显示，蜂鸣器只在事件沿响，三键只做长按操作；标定参数写 Flash；USART1 输出 CSV 与日志

---

## 0. 速览

| 项 | 现状 |
|---|---|
| 采样 | USART2 = B 称量（称盘）、USART3 = A 参考（砝码槽）；每路 10 Hz，合计 20 样本/s |
| 时间基准 | DWT 周期计数器 → 64 位 µs 时间轴，帧完成（UART IDLE）时刻打戳 |
| 算法 | 变化沿流 + 延迟 3 点 Hampel → 45 s 窗自对齐（τ̂）→ A 三次插值配对 → 比值 → 延迟 5 点 Hampel → 估计器（待机/称量、锁存、精化、回臂） |
| 显示 | UART4 数码管，5 Hz 刷新；优先级：预备 > 清零 > 锁定读数 > 实时质量 |
| 交互 | 三键**只响应长按**：PB13 无功能、PB14 长按=清零（零点重锚）、PB15 长按=修正 k（500 g 跨度校正）；扩展键 PA15（KEY4）**开机 10 s 内按住 2 s** 触发标定；短按无动作 |
| 蜂鸣 | 1 短=段推进、2 短=成功、3 短=软失败、1 长=硬错误；上电静音，运行期无翻页音 |
| 标定 | 500 g 两点比值，k = M/Δr，Flash Sector 11 掉电保存（CRC32） |
| 未接入 | 分页 UI（代码中不存在）、TIM10、模块清零指令 |

## 1. 硬件接口

### 1.1 MCU、时钟与存储

| 项目 | 配置 | 依据 |
|---|---|---|
| MCU | STM32F407ZGTx（LQFP144） | `dual_scale.ioc` |
| 时钟源 | **HSI 16 MHz** → PLL（M=8，N=168，P=2） | `main.c` `SystemClock_Config()` |
| SYSCLK | 168 MHz | 同上 |
| AHB / APB1 / APB2 | 168 MHz / 42 MHz / 84 MHz | APB1÷4、APB2÷2 |
| 定时器时钟 | TIM2/TIM3/TIM10 = 84 MHz（APB1×2） | 由 APB1 分频非 1 推得 |
| Flash 等待 | 5 WS（`FLASH_LATENCY_5`），电源档 Scale1 | `main.c` |
| SysTick | 1 ms（`HAL_Init()` 默认），HAL 时基来源 | HAL |
| µs 时间轴 | DWT->CYCCNT，`SystemCoreClock/1e6` 周期 = 1 µs，软件累加成 64 位 | `dwt_time.c` |
| 栈 / 堆 | 栈 4 KB（`Stack_Size=0x1000`），堆 0x200（代码不使用 `malloc`） | `MDK-ARM/startup_stm32f407xx.s` |
| 运行库 | 无 MicroLIB；**不使用** `printf/vsnprintf`，格式化全部自实现 | `dbg_uart.c`、`digit_tube.c` 注释 |
| 看门狗 | **IWDG 已启用**：LSI/128 + RLR=4095 ≈ 16.4 s（11.15~30.84 s），主循环喂狗、Flash 擦除前补喂；睡眠期间不启动 | 见 §3.11 |
| 大块 RAM | `AppScale g_scale` ≈ 57 KB 静态变量；录制模式下被复用为样本环 | `main.c`、`qsh_drv.h` |
| 参数区 | Flash Sector 11，起始 `0x080E0000`（128 KB 扇区） | `app_calib.h` `APP_CALIB_FLASH_ADDR` |

> 注意：`.ioc` 中 PH0/PH1 被配置为 **HSE 8 MHz 外部晶振**，但 `SystemClock_Config()` 只启用了 HSI，HSE 从未上电。即实际运行时钟是内部 HSI 经 PLL，8 MHz 晶振不参与。

### 1.3 中断与优先级

NVIC 优先级组 = GROUP_4（4 位抢占）。下表数字越小优先级越高。

| 中断 | 优先级 | 触发源 | 处理内容 |
|---|---|---|---|
| TIM2_IRQn | 0 | 10 Hz 更新 | 向 A、B 两路各发一条"读内码"命令（仅 `s_ready=1` 且探针空闲时） |
| USART2_IRQn | 0 | B 通道 RX/TX | `HAL_UART_IRQHandler` + `QshDrv_IdleIRQ` 断帧 |
| USART3_IRQn | 0 | A 通道 RX/TX | 同上 |
| DMA1_Stream5/Stream6 | 0 | USART2 RX/TX | HAL DMA 搬运 |
| DMA1_Stream1/Stream3 | 0 | USART3 RX/TX | HAL DMA 搬运 |
| EXTI15_10_IRQn | 0 | PB13/14/15 下降沿 | 置按键触发标志 |
| UART4_IRQn | 3 | 数码管 TX 完成 | `HAL_UART_IRQHandler`，释放发送缓冲 |
| SysTick | 15 | 1 ms | `HAL_IncTick()` |

所有中断里只做搬运、打时间戳、置标志；协议解析、算法、显示、按键状态机全部在主循环。

### 1.4 电池检测接口（PA4，2026-11-15 已启用）

外部电路（硬件侧）：

```
12V 电池 + ──[100 kΩ]──┬── PA4 (ADC1_IN4)
                        │
                    [20 kΩ]
                        │
                       GND
```

由此可得：

| 量 | 关系式 | 12 V 时数值 |
|---|---|---|
| 分压比 | V(PA4) = Vbat × 20k / (100k + 20k) = Vbat / 6 | 2.000 V |
| 电池电压 | Vbat = 6 × V(PA4) | — |
| 由 ADC 码反算 | Vbat = code × (3.3 / 4095) × 6 ≈ code × 4.835 mV | code ≈ 2482 |
| 可测上限 | 3.3 V × 6 = 19.8 V（4095 码） | — |
| 分辨率 | 4.84 mV/LSB（≈0.04 % FS） | — |
| 分压源阻抗 | 100k ∥ 20k ≈ 16.7 kΩ | 分压电流 100 µA |

代码侧（已实现）：

- `MX_ADC1_Init()`：ADC1、12 bit、右对齐、单通道、软件触发、通道 4（PA4 模拟）。
- **采样时间已由 3 周期改为 `ADC_SAMPLETIME_480CYCLES`**（16.7 kΩ 源阻抗需要足够采样窗；3 周期只有 ~1τ，读数会偏低）。CubeMX 里也要同步改成 480，否则重新生成会回退。
- `main.c` 的 `BatVolt_ReadMv()`：16 次采集中值 → mV（`code × 3300 × 6 / 4095`）。
- 开机 + 每 10 s 检测；**<11.4 V 报警、>11.6 V 清除**（0.2 V 迟滞）。
- 报警动作：3 短鸣 + 数码管闪 `11.4U` 10 s → 直接 `RequestSleepReset()` 休眠；低电期间禁用 KEY4 标定；10 s 内长按中键可取消强制休眠（应急使用）。
- 建议硬件在 PA4 对地加 **100 nF**，进一步稳住采样；分压常驻漏流 100 µA（休眠时也在漏，电池小的话考虑加 MOS 开关）。

### 1.5 称重传感器接口（QSH-H，MODBUS-RTU over RS485）

| 项 | 通道 A（参考） | 通道 B（称量） |
|---|---|---|
| UART | USART3 | USART2 |
| 引脚 | PB10 TX / PB11 RX | PA2 TX / PA3 RX |
| 波特率 | 9600-8-N-1 | 9600-8-N-1 |
| DMA | RX=DMA1_S1，TX=DMA1_S3 | RX=DMA1_S5，TX=DMA1_S6 |
| 角色 | 砝码槽/参考梁，做共模相消 | 称盘，真正的载荷 |
| CSV `sensor` 字段 | `0` | `1` |

协议要点（`qsh_drv.c`）：

- 从站地址固定 `0x01`（两条独立总线，互不冲突），CRC16/MODBUS（多项式 0xA001，低字节在前）。
- **读内码**：`01 03 00 17 00 02` + CRC（协议地址 0x17–0x18，32 位原码）。响应 9 字节：`01 03 04 <b31..b24> <b23..b16> <b15..b8> <b7..b0> <crcL> <crcH>`。读的是**内码**而不是 40001 净重，绕过模块侧零点管理。
- **上电会话配置**：每通道依次写 3 个单寄存器（功能码 06）：

  | 代码中寄存器地址 | 写入值 | 注释语义（代码/README 记为 40005/40006/40007） |
  |---|---|---|
  | `0x0005` | `0x0001` | 开机不置零 |
  | `0x0006` | `0x0000` | 滤波弱 |
  | `0x0007` | `0x0000` | 蠕动（零点跟踪）关 |

  每条等回显（超时 250 ms），失败重试 3 次，失败也继续下一条；两通道 6 条全部走完置 `s_ready=1`，TIM2 才开始轮询。计数器见 `cfgAck/cfgFail`。
- **模块清零** `01 06 00 04 00 01` 有实现（`QshDrv_SendZero`），但当前代码**没有任何调用点**；清零语义完全由主机算法层承担。
- **断帧**：DMA 常驻接收 32 字节 + 开 UART IDLE 中断；IDLE 到来时取 DMA 剩余计数算出帧长、打 DWT µs 时间戳、重启 DMA（`qsh_frame.c`）。
- 每通道一帧只保留一份待取（`framePending`），主循环取走前又来新帧则计 `overrunCnt`。
- 样本结构 `QshSample_t`：`ch / code(int32) / tUs(uint64) / dup / seq`，24 B；环形缓冲正常模式 128 条（20 样本/s → 6.4 s）。
- 最新值与数据年龄：`QshDrv_Last()`（`ageMs` 用于心跳和"新鲜度<500 ms"判据）。

### 1.6 数码管接口（UART4）

| 项 | 值 |
|---|---|
| 引脚 | PA0 = TX，PA1 = RX（本工程只用 TX） |
| 参数 | 9600-8-N-1，`HAL_UART_Transmit_IT` 非阻塞 |
| 协议 | 整帧 `$001,<字段>#`，例如 `$001,12.3#`；黑屏 `$001,#`；占位 `$001,---#` |
| 字段格式 | 有符号十进制，最多 1 位小数，字段最长 `-9999.9`（7 字符），字段缓冲 16 B |
| 刷新策略 | 内容变化后最快 20 Hz 发出；内容不变每 300 ms 重发一次（防上电慢/丢帧） |
| 亮度 | 模块亮度帧 `$001,00<n>%`（n=0~4，4 最亮），上电默认下发 4 档；与显示帧之间强制留 30 ms 空档（否则会被并帧丢弃），另按 2 s 周期重发防丢帧 |
| 上电 | `DigitTube_Init()` 先发亮度 4 档，再发 `666`，随后主循环接管 |
| 断线表现 | B 通道 >3 s 无数据 → 主循环调 `DigitTube_ShowBlackScreen()` 黑屏 |

### 1.7 蜂鸣器（TIM3_CH1 / PA6）

| 项 | 值 |
|---|---|
| 类型 | 无源蜂鸣器，PWM 驱动 |
| 频率 | 2 kHz（84 MHz / 84 / 500），谐振点，勿改 |
| 音量 | CCR 0–249（0 = 静音，249 = 50 % 占空比最大声；再高反而变小），默认 `BEEPER_LEVEL = 200`（约 −0.4 dB，2026-11-14 由 75 提高，现场反馈偏小） |
| 驱动方式 | 主循环 `Beeper_Process()` 轮询 HAL tick，无新中断 |
| 队列语义 | 正在响时新请求**直接丢弃**，不排队 |

预定义音型与当前调用点：

| 音型 | 波形 | 含义 | 当前调用点 |
|---|---|---|---|
| `Beeper_Tick()` | 1 × 40 ms | 段推进/提示 | 预备模式 空盘段 → 提示放砝码；**上电建基线阶段与 "---" 闪烁同步（1 Hz，首次 ready 后停止）** |
| `Beeper_Ok()` | 2 × 80 ms | 成功 | 零点重锚成功、跨度校正成功、预备标定提交成功、预备结果全通过；**连续空载 5 分钟自动休眠前（2 短后 350 ms 进休眠）** |
| `Beeper_Fail()` | 3 × 80 ms | 软失败 | 清零错误码 9100/9200/9300、预备结果有失败位 |
| `Beeper_Error()` | 1 × 400 ms | 硬错误 | 清零错误码 7777（k 超范围） |
| `Beeper_Beep(1,80,0)` | 1 × 80 ms | 操作已开始 | 长按进入零点/跨度采集的瞬间 |
| `Beeper_Beep(1,200,100)` | 1 × 200 ms | — | 跨度校正成功（与零点的 2 短区分） |
| `Beeper_Beep(3,80,80)` | 3 × 80 ms | 标定已触发 | **KEY4（PA15）开机窗口触发后连响三下**（等建基线提示音播完再发，保证三声完整） |

上电 `Beeper_Init()` 立即 CCR=0 静音；正常称量过程不发声。

### 1.8 按键接口（PB13 / PB14 / PB15 + 扩展 PA15）

电气：内部上拉、按下为低、EXTI 下降沿触发 + 主循环电平复核；消抖 15 ms，长按门限 800 ms。

| 物理位置 | 引脚 | 代码索引 | 短按（<800 ms） | 长按（≥800 ms） |
|---|---|---|---|---|
| 左键 | PB15 | KEY2 | 无动作 | **修正 k**：带 500 g 标准砝码、估计器锁定且读数在 **400–600** 时长按 → 跨度校正；采集中再长按=中止 |
| 中键 | PB14 | KEY1 | 无动作 | **清零**：空盘长按 → 零点重锚（不写 Flash）；盘上有负载时入口不满足 → 9300；采集中再长按=中止 |
| 右键 | PB13 | KEY0 | 无动作 | **无功能**（仅保留为休眠唤醒源） |
| 扩展键 KEY4 | PA15 | —（GPIO 轮询） | 无动作 | **开机 10 s 内持续按住 2 s** → 触发标定：连响三下，等建基线完成（--- 消失）→ 进入预备标定；10 s 内未触发则本次开机不再触发 |

补充事实：

- 短按事件其实会被 `keys.c` 生成，但 `main.c` 里 `Keys_Take(0)/1/2` 只判断 `KEY_EV_LONG`，短按被就地丢弃；KEY0 的长按事件被消费但无动作。
- KEY4 是 PA15 普通 GPIO（输入上拉，按下低），**不是 EXTI**：主循环轮询，10 s 窗口 + 2 s 持续低电平。PA15 复位后是 JTDI，配成普通输入即可当 GPIO；SWD 仍在 PA13/PA14，不影响下载调试。
- 当前**没有"前一页/确认/下一页"分页逻辑**，也没有切页提示音。

## 2. 软件结构（模块地图）

无 RTOS，裸机"主循环 + 中断"。分层如下：

| 层 | 文件 | 职责 | 上下文 |
|---|---|---|---|
| 入口 | `main.c` | 初始化、主循环调度、事件→显示/蜂鸣、调试输出 | 主循环 |
| 时基 | `dwt_time.c/h` | DWT 周期计数 → 64 位 µs 公共时间轴 | 任意（关中断累加） |
| 通信底层 | `qsh_frame.c/h` | IDLE + DMA 断帧、盖 µs 时间戳 | ISR + 主循环 |
| 传感器驱动 | `qsh_drv.c/h` | MODBUS 组帧/校验、上电配置状态机、10 Hz 轮询、样本环、录制、寄存器探针 | 主循环 + TIM2 ISR |
| 显示 | `digit_tube.c/h` | UART4 数码管协议、非阻塞发送、心跳重发 | 主循环 |
| 人机 | `keys.c/h` | 三键消抖/短长按、EXTI 回调 | 主循环 + EXTI ISR |
| 人机 | `beeper.c/h` | PWM 音型状态机 | 主循环 |
| 应用 | `app/app_scale.c/h` | 样本 → 算法流水线 → 读数事件 | 主循环 |
| 应用 | `app/app_calib.c/h` | 两点标定提交、Flash 读写/CRC32 | 主循环 |

## 3. 运行逻辑

### 3.1 启动序列（`main()`）

1. `HAL_Init()` → SysTick 1 ms。
2. `SystemClock_Config()` → HSI/PLL 168 MHz。
3. 外设初始化：`MX_GPIO_Init` → `MX_DMA_Init` → `MX_USART2_UART_Init` → `MX_TIM2_Init` → `MX_USART3_UART_Init` → `MX_UART4_Init` → `MX_TIM3_Init` → `MX_TIM10_Init` → `MX_ADC1_Init`。
4. `DwtTime_Init()`、`Dbg_Init()`（PA9 首行日志）、`Keys_Init()`。
5. `QshDrv_Init()`：构造 3 条配置写命令 + 读命令，`QshFrame_Start()` 启动两路 DMA 接收，配置状态机置 `BST_SEND`。
6. `HAL_TIM_Base_Start_IT(&htim2)`：10 Hz 节拍照常走，但只有 `s_ready=1` 时才真的发轮询。
7. `Beeper_Init()`（PWM 起、立即静音）、`DigitTube_Init()`（发 666）。
8. 算法参数：先取 `algo_params_default`，再覆盖为台架占位值（`k=1467.9`、`r_empty=0.35222`、`zero_codes_a=20220`、`zero_codes_b=14401`、`presence_center_codes=90100`），`AppScaleInit(&g_scale, ...)`。
9. `AppCalibLoad(&g_scale)`：Flash 记录 magic+CRC 通过则覆盖 `k / r_empty / presence_center_codes`，否则保留占位值并打印 `# CALIB flash empty/invalid -> defaults`。
10. 打印 `# BOOT`、`# FORMAT`、`# APP_SCALE` 等启动日志，进入主循环。

### 3.2 主循环每一轮的固定顺序

```
while (1) {
  ① Keys_Process()        按键消抖/长短按判定
  ② QshDrv_Process()      取帧→解析→入环；BootStep()；ProbeStep()
  ③ DigitTube_Process()   数码管发送/心跳重发
  ④ Beeper_Process()      音型相位推进
  ⑤ 若 g_recAlgoHold==0：消费全部样本 → CSV → AppScaleFeed/Process → 事件
  ⑥ B 通道 >3 s 无数据 → 数码管黑屏
  ⑦ 录制模式：数码管显示 B 原始码/10（覆盖正常显示）
  ⑧ g_recArm 沿检测 → QshDrv_RecBegin/RecEnd
  ⑨ 按键分发：PB14 长按 → 清零；PB15 长按 → 修正 k（500 g 跨度）；KEY4（PA15，开机 10 s 内 2 s）→ 标定；PB13 无功能；驱动两个状态机 + 提示音
  ⑩ 预备驱动：通信统计/实时质量喂入、AppPrepPoll、提交/结果音
  ⑪ 每 200 ms：刷新数码管（预备 > 清零 > 锁定读数 > 实时）
  ⑫ 每 1000 ms：心跳 # STAT / # ALG / # CODE（# REC）
}
```

### 3.3 采样链（从 RS485 到读数事件）

1. **TIM2 10 Hz**：向 A、B 各发 `01 03 00 17 00 02`（探针期间暂停）。
2. **IDLE 中断**：模块应答结束 → 记帧长 → `DwtTime_NowUs()` 打戳 → `framePending`。
3. **`QshDrv_Process`**：`QshFrame_Take` 取帧 → 校验（地址/功能码/字节数/CRC16）→ 解析 32 位内码 → 判 `dup` → 更新 `s_lastCode/s_lastTick/s_seq` → 入环（录满则停止入环但继续计数）。
4. **主循环**：`QshDrv_PopSample` 逐条取出 → 输出 CSV 行 → `AppScaleFeed(&g_scale, t, ch, code)` → `AppScaleProcess(&g_scale, t)` → `AppScalePopEvent` 取事件。
5. **事件→显示状态**：`READING` 置锁定并清闪烁等级；`REFINE` 刷新锁定值；`REARM`/`RESTEP` 解除锁定回到实时显示。
6. **断流保护**：B 通道（称量）超过 3 s 无样本 → 黑屏一次（通信故障可见）。

样本节奏：每路 10 Hz，共 20 样本/s；内环 128 条可缓冲 6.4 s。

### 3.4 算法流水线（`app_scale.c` + `algo/*`）

逐层说明（参数均为 `algo_params.h` 冻结值）：

**第 1 层 变化沿流 + 延迟 Hampel（源头）**
每通道原始样本先做"变化沿"筛选（`code` 与上次相同则丢弃），保留原始 FIFO 8 点；对第 `n-4` 点做半窗 k=3、阈值 h=3.0 的 Hampel，得到清洗流（延迟 3 点）。`AlgoStream` 上板容量 512 点 ≈51 s。

**第 2 层 慢环自对齐（`algo_align.c`）**
首个清洗样本确定锚点；此后每 2.5 s 用"最近 45 s 窗"（丢头部 8 s）在 20 Hz 网格上重采样 A/B 两路，0.05–1 Hz 带通，做相位相关：
- `rho ≥ 0.998` 且非静止 → 该窗 τ̂ 入 τ 历史，权重 = `w_rms × w_rho`，其中 `w_rms = clamp((rms_b/0.06)^4, 0.02, 1)`、`w_rho = clamp(0.004/(1−ρ²), 0.1, 4)`；
- 每个窗都发一条 `APP_EV_ALIGN` 事件（调试行 `# ALIGN`）。

**第 3 层 快环配对（比值）**
B 新清洗样本进待配队列，等 A 清洗流末端越过 `tb + 0.15 s` 才配：
- τ̂( tb ) 由 τ 历史外推（`AlgoTauEval`）；
- A 在 `tb + τ̂` 处做 4 点三次插值，最大间隙 0.25 s；
- 在位保护：A 插值值落在 `0.75~1.25 × presence_center_codes`（默认 67 575~112 625）之外则拒绝并计缺口；
- 比值 `r = (B − zero_codes_b) / (A − zero_codes_a)`。

静态回退：若配对饥饿 >3 s，则用同拍原始码对直接算 r（静态无 α 泄漏），配对恢复后自动切回。

**第 4 层 比值清洗**
比值进 12 点 FIFO，对 `n-6` 点做 k=5、h=3.0 的 Hampel（延迟 5 点）；MAD 地板由最近 256 个比值的差分噪声估计（每 64 对更新）。

**第 5 层 估计器（`algo_est.c`）**

| 阶段 | 判据 | 动作 |
|---|---|---|
| 待机 IDLE | 基线 = 最近 ≤600 个比值的**中值**；σ = 1.4826×MAD（下限 4e-5） | 持续更新基线 |
| 开事件 | 超基线 `5σ` 连续 3 点，且 `k·Δr ≥ 2 g` 且 `k·(r−r_empty) ≥ 2 g` | 转 WEIGHING，记录阶跃时刻 |
| 向下重锚 | 低于基线 `5σ` 连续 15 点 | 基线搬家（防瞬态下冲误判） |
| 锁存 | 阶跃后 1.2 s 起算、最近 3 s（不少于 2 s）窗的 10 % 截尾均值，`rel_std < 5e-4` 且质量 ≥2 g | 生成读数，进锁定态 |
| 精化 | 锁定后 30 s 滑动窗截尾均值持续刷新 | 读数随时间收敛 |
| 回臂 | 回到基线 `3σ` 内**或**质量在 `±rearm_floor_g`（默认 1 g）内，连续 3 点 | 回 IDLE，定稿（`REARM`）。质量域兜底用于取走重物后的几克残留（3σ 仅 ≈0.18 g，残留会让状态卡在称量态） |
| 盘中增减 | `abs(1 s 快均值 − 读数均值) × k` 超门限（静水 2 g / 涌浪 5 g）连续 5 点 | 定稿并开新事件（`RESTEP`） |
| 防卡死 | 未锁定、超时 10 s 且距基线 <5 g | 强制回 IDLE 重建基线 |

**第 6 层 可信度分级**：`level 0` 可信 / `1` 勉强 / `2` 超限。判据：ρ<0.95 或 `rel_std≥8e-4` 或缺口率>10 % → 硬失败；ρ<0.985 或 `rel_std≥4e-4` → 软失败。显示上用常亮/慢闪/快闪表达。

**实时显示值**：`k × (最新清洗比值 − 基线)`；仅当 `idle_n ≥ 30` 且 `k ≠ 0` 才算就绪，否则数码管闪 `---`。

### 3.6 按键分发与模式互斥

```
KEY4/PA15：开机 10 s 内持续按住 2 s → 连响三下 → 等建基线完成 → 预备标定
PB14 长按（且预备空闲，且非录制）→ 清零（空盘零点重锚） 进入/中止
PB15 长按（且预备空闲，且非录制）→ 修正 k（500 g 跨度校正） 进入/中止
PB13 长按 → 无功能（仅保留为休眠唤醒源）
```

- 预备模式（`app_prep.c`）：通信门 5 s（双通道新鲜 <500 ms、错帧率 <0.5 %、环满丢弃为 0；入口粗查 B 码 >80 000 判"未清盘"）→ 空盘 10 s（|实时质量中值| ≤0.5 g，采 r0）→ 提示放砝码（60 s 超时，比值域检测放置，门限 0.03≈44 g）→ 稳定 2 s → 采集 10 s（+14 s 保险）→ 算 `k=500/Δr`，门限 `Δr>0.15`、`k∈[1250,1650]` → 内存生效 + Flash → 结果码 5 s。
- 清零/修正（`app_zero.c`，2026-11-15 分键）：**中键**只做空盘零点重锚（`baseline=10 s/100 样本中值`，不写 Flash）；**左键**做跨度校正（要求估计器锁定且读数在 **500 g ±20 %（400–600 g）** 窗内，`k=500/(r1−baseline)`，走 `AppCalibCommit` 写 Flash），不在窗内直接 9300、不再回退成零点。两个上下文都是 10 s/100 样本、`σ_mad ≤1 g`、偏移门 5 g（跨度另有 ±20% 窗复核）。注意 ±20% 窗意味着 400–600 g 的任何物体都会被当成 500 g 标准件，k 误差最大 −16.7%~+25%，由 `k∈[1250,1650]` 再挡掉一部分（典型机实际可接受约 443~584 g）。
- 互斥（以 `main.c` 的实际判据为准）：清零仅在"预备空闲 + 未录制"时可进入；预备仅在"清零空闲"时可进入，录制期间并不拦截——但录制时样本不进算法（`g_recAlgoHold`），预备实际无法完成。

### 3.7 标定与持久化

- 形式：两点比值标定。空盘比值 `r0`、加 500 g 标准砝码比值 `r1`，`k = 500 / (r1 − r0)`（`APP_CALIB_MASS_G = 500`）。
- 提交校验：`Δr > 0.30 × (M/1000)` 即 >0.15；`k ∈ [1250, 1650]`。
- 记录 `AppCalibRec`（56 B）：magic `"CAL1"`、seq、`k_g_per_r`、`r_empty`、`presence_center_codes`、`zero_codes_a`、`zero_codes_b`、CRC32。
- 存储：擦除并重写 Flash Sector 11（`0x080E0000`），按 32 位字逐字编程（x64 双字编程在真机上会触发 PGPERR，已改为 x32）。
- 失败诊断：`g_calib_flash_rc` 低 4 位为步骤（1 Unlock / 2 Erase / 3 Program），高 8 位为 HAL 状态。k 通过门限即先内存生效，Flash 失败只降级为 `6666` 提示。
- 开机加载只回填 3 个字段（k、r_empty、presence_center），零点偏置不随记录恢复。

### 3.10 自动休眠（2026-11-15：打标记 + 软复位方案）

- **条件**：双通道数据新鲜（<500 ms）、实时质量就绪且**连续 5 分钟（300 s）**处于 **−3 g ~ +3 g**、无称量事件/锁存、无清零/预备采集、非录制、无按键按住。任一条件不满足则重新计时。
- **睡前动作**：`Beeper_Ok()`（2 短）→ 350 ms 等提示音播完 → 停 TIM2 轮询 → 蜂鸣器 CCR=0 → 数码管亮度 0（等帧真正发完）→ `RTC->BKP0R = 0x57444753("WDGS")`（备份寄存器，跨系统复位保留）→ `NVIC_SystemReset()`。
- **为什么不再直接 STOP**：IWDG 由 LSI 驱动，**在 STOP 模式下仍计数**，直接 STOP 会被每 11.15~30.84 s 复位一次，设备根本睡不住。
- **睡眠启动**（复位后、`SystemClock_Config` 之前）：只有 `RCC->CSR.SFTRSTF`（软件复位）**且** `BKP0R == 魔术值` 才进入；进入后先清 `BKP0R`（保证之后任何复位都回正常启动），再执行 `SleepBoot()`：**不启动 IWDG、不初始化 UART/数码管/驱动**，只把 PA6 拉低、配按键 EXTI、PA2/PA3/PB10/PB11 置 analog、清 pending、`HAL_SuspendTick()`，然后 `HAL_PWR_EnterSTOPMode(PWR_LOWPOWERREGULATOR_ON, WFI)`。
- **唤醒**：PB13/PB14/PB15 任一按键 EXTI → `NVIC_SystemReset()` 整机复位，回到正常启动（IWDG 重新开启）。
- **复位原因校验**：加 `SFTRSTF` 判断是为了防 VBAT 保持 BKP 时，整机断电再上电被误判成睡眠启动（设备会"躺死"）。
- **防误触**：唤醒复位时按键通常还按着，`Keys_Init()` 会置"等释放"标志，三键全松开前不处理按键。
- **调试**：`SLEEP_KEEP_SWD=1` 时在 SleepBoot 里设 `DBGMCU_CR.DBG_STOP`；量产必须为 0。
- **注意**：休眠期间 RS485 模块仍由外部供电；若模块与 MCU 共用电源，则不存在倒灌问题，引脚 analog 也无害。

### 3.11 独立看门狗（IWDG，2026-11-15）

- **参数**：由 CubeMX 决定（当前 `.ioc`：预分频 **128** + RLR 4095）→ 典型 **16.38 s @32 kHz**，最快 **11.15 s**（LSI 47 kHz）~ 最慢 **30.84 s**（17 kHz）；F407 无窗口模式。Flash 擦除最大按 4 s，余量充足；代价是卡死要 11~31 s 才复位（想更快可改 `/64` → 5.58~15.4 s）。
- **启动**：`MX_IWDG_Init()`（初始化序列里）；**睡眠启动路径不启动**。
- **喂狗**：主循环末尾 `AppWdg_Feed()`（`KR=0xAAAA`）每轮一次；`flash_save()` 擦 Sector 11 前补一次。喂狗与预分频无关，改参数只改 `.ioc`。
- **禁止**在中断里喂狗；`Error_Handler()` 不喂，靠 IWDG 超时复位自恢复。
- **调试**：`__HAL_DBGMCU_FREEZE_IWDG()`（断点时不复位）。
- **启动日志**：IWDG 复位后打印 `# RESET iwdg (watchdog)`；正常启动会做一次 BKP0R 写/读自检，失败打印 `# WARN RTC BKP write/read failed`。
- **前提**：option byte `IWDG_SW = 1`（软件启动），否则复位关不掉 IWDG，§3.10 的方案失效。

### 3.12 电池低压检测（PA4，2026-11-15）

- **采样**：`BatVolt_ReadMv()` 16 次取中值；ADC1_IN4、12 bit、采样时间 **480 周期**（16.7 kΩ 源阻抗）。
- **阈值**：< **11.4 V** 报警；> **11.6 V** 清除（0.2 V 迟滞）。
- **检测时机**：开机第一轮 + 每 10 s 复检。
- **报警动作**：3 短鸣（80 ms×3）+ 数码管闪烁 **`11.4U`**（U=请充电）10 s → `RequestSleepReset()` 直接休眠（不再额外 2 短鸣）。
- **低电禁标定**：本次开机只要出现过低电，KEY4 标定被禁用（弱电写 Flash 危险）。
- **应急取消**：10 s 内长按中键 → 取消强制休眠，恢复正常显示（本次开机不再重复报警）。
- **调试**：`# BAT <mv> mV`、`# BAT low ...`、`# BAT ok ...`、`# BAT cancel`、`# BAT sleep`。
- **硬件**：PA4 建议加 100 nF 到地；分压常驻漏流 100 µA（休眠时也在漏，电池小可选 MOS 开关）。
- **注意**：此功能假设 UPS 的 12V 输出是**电池直出**；若 UPS 稳压输出，电池跌到 11.4 V 时 12V 轨仍是 12.0 V，检测不到。
